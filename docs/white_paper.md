# Industry 4.0 Digital Twin — White Paper

## Executive Summary

Manufacturing, chemical processing and oil & gas operations need improved visibility, predictive maintenance and autonomous decision support to reduce downtime and increase Overall Equipment Effectiveness (OEE). This project delivers an end-to-end open-source digital twin platform that ingests OT telemetry (OPC UA, MQTT), stores high-resolution time-series, runs simulations and ML models, and exposes dashboards and control interfaces for a controlled autonomous pilot. The expected outcomes are real-time monitoring, predictive maintenance (target: reduce unplanned downtime ≥30%), and OEE improvement (target: ≥10%).

## Architecture Overview

- Edge Layer: Gateways run Node-RED + OPC UA adapters (`node-opcua` / `open62541`) to collect PLC/SCADA signals. Gateways publish telemetry to MQTT (Eclipse Mosquitto).
- Ingestion & Streaming: MQTT broker → optional MQTT→Kafka bridge → Kafka topics for durability and replay. Stream processors normalize and enrich events.
- Storage: TimescaleDB (Postgres) for time-series and aggregates; PostgreSQL for metadata and twin state; optional object store for raw event archives.
- Services: Microservices (FastAPI/.NET) implement asset registry, telemetry APIs, OEE computation, and model-serving endpoints (BentoML/MLflow).
- Modeling & Simulation: Simulation services (SimPy / OpenModelica) provide replay and what-if scenarios; ML training pipelines consume historical data, register models, and serve real-time inference.
- Visualization & Demo App: Grafana for operational dashboards; a React demo app provides a curated interview experience: live telemetry, twin inspector, control panel, prediction panel, and replay mode.
- Security & Ops: Keycloak for SSO/RBAC, Prometheus + Grafana for metrics, OpenSearch for logs, Helm + ArgoCD (GitOps) for k8s deployments.

## Data & KPI Model

- Telemetry message: `{timestamp, device_id, metric, value, unit, tags}`
- Aggregates: 1s raw → 1m/5m continuous aggregates; store raw 90 days, aggregates 2 years.
- KPIs: OEE = Availability × Performance × Quality; MAPE for model accuracy; MTTR/MTBF for maintenance.

## Security & Compliance

- TLS for all ingress; mTLS for service-to-service where appropriate.
- RBAC via Keycloak, audit logs stored in OpenSearch.
- Network segmentation (edge vs cloud) and least privilege for device credentials.
